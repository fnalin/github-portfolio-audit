# Task 00 — Reproducible Repository Metadata Collection

## Status

COMPLETED

## Objective

Create a reproducible and read-only mechanism for collecting GitHub repository metadata for the `fnalin` account.

The resulting dataset will become the canonical metadata input for subsequent portfolio-audit tasks.

This task must not analyze, classify, modify, archive, delete, or clone repositories.

---

## Current Inputs

Existing local metadata files may be used only for validation:

- `data/github-repos-1.json`
- `data/github-repos-2.json`

These files are legacy inputs generated manually and must not be modified.

They are not the desired long-term data source.

---

## Required Output

Create:

- `scripts/fetch-repositories.sh`
- `data/repositories.json`

The script must be the reproducible source for generating `data/repositories.json`.

Raw JSON data must remain excluded from Git version control.

---

## GitHub Access

Prefer GitHub CLI (`gh`) for GitHub API access.

The script must assume that authentication is handled externally by GitHub CLI.

Do not:

- embed GitHub tokens;
- request tokens interactively;
- store credentials;
- print credentials;
- create `.env` files containing credentials.

If `gh` is unavailable or authentication is not configured, stop and report the requirement instead of implementing an insecure workaround.

---

## Script Requirements

`scripts/fetch-repositories.sh` must:

1. use strict shell behavior where appropriate;
2. verify that `gh` is available;
3. verify that GitHub authentication is available;
4. retrieve repository metadata for the `fnalin` account;
5. handle pagination correctly;
6. retrieve repositories publicly visible in the `fnalin` GitHub portfolio;
7. produce one valid JSON array;
8. write the result to:

   `data/repositories.json`

9. fail clearly when collection cannot be completed;
10. avoid modifying GitHub in any way.

The script must be safe to execute repeatedly.

Running it again should replace the generated metadata dataset rather than append duplicate repositories.

---

## Metadata

Preserve GitHub API repository metadata rather than prematurely reducing the dataset to only fields currently needed by Task 01.

The generated JSON should retain enough information to support future audit tasks without requiring unnecessary repeated API calls.

Do not add invented metadata.

---

## Validation

After generating `data/repositories.json`, validate:

- the file contains valid JSON;
- the root value is an array;
- repository names are present;
- repository IDs are unique;
- repository names are unique for the account;
- no duplicate repositories were introduced by pagination;
- the repository count is reasonable compared with the existing legacy JSON files.

If the new repository count differs from the legacy files, investigate whether the difference is explained by:

- repositories created or removed since the legacy export;
- pagination;
- visibility;
- authentication context;
- duplicate legacy data;
- differences in GitHub API behavior.

Do not force the new dataset to match the legacy files.

The GitHub API result generated by the reproducible process should remain the source of truth once validated.

---

## Security

This task is strictly read-only toward GitHub.

Do NOT:

- create repositories;
- modify repositories;
- archive repositories;
- delete repositories;
- change visibility;
- change repository settings;
- push commits to GitHub repositories;
- modify repository topics or descriptions.

Never write authentication credentials into generated files.

If unexpected sensitive data is encountered, do not reproduce it unnecessarily.

---

## Repository Changes

This task may create or modify only:

- `scripts/fetch-repositories.sh`
- `data/repositories.json`
- this task's status, when appropriate.

Remember that `data/repositories.json` is ignored by Git and must not be committed.

Do not modify `CLAUDE.md`, `README.md`, `docs/decisions.md`, or Task 01 during execution.

## Acceptance Criteria

The task is complete only when:

- `scripts/fetch-repositories.sh` exists;
- the script uses read-only GitHub operations;
- no credentials are embedded in the script;
- pagination is handled correctly;
- the script can regenerate the dataset;
- `data/repositories.json` exists;
- `data/repositories.json` contains valid JSON;
- the root JSON value is an array;
- repository IDs are unique;
- repository names are unique;
- repository counts have been validated against the legacy exports;
- any meaningful count difference has been explained;
- no GitHub repository has been modified;
- no repository has been cloned;
- the generated JSON remains ignored by Git.

After satisfying these criteria, STOP and present a concise summary to the user.
